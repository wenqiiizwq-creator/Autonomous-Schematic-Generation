# 草案：下游约束表——原理图阶段定下、要由 PCB、结构、样机落实的要求必须交出去

2026-11-13，已按“照草案写入”实施（纲要哈希 d99519396d5307fa）。

## 起因

AD9361 板（桌面 `ASG实测-AD9361模块-2026-11-11`）：U301 估算结温 104 ℃，III 级降额值 85 ℃，额定 110 ℃。
ASG 判出了应力超幅，也写了散热办法，但这条要求没有交给 PCB 和结构：

| 写在哪 | 写了什么 | 交给谁 |
|---|---|---|
| 计算 RF-TJ 的 `improvement` | 底部散热过孔阵列接完整地平面，必要时加散热片 | 无人：只是报告“应力风险”表里的一格 |
| 待办 W-RF-TJ（validation，open，P0） | 样机 45 ℃ 实测壳温，超 85 ℃ 再加散热片或限模式 | 样板调试：等板子做出来再说 |
| 报告“技术转交要求” | 两条射频调试项 | 没有散热 |

结果 PCB 布板脚本对 U301 没做任何散热处理，正面没给散热片留位置。
样机实测只能“确认”散热够不够，散热本身要在样机之前由 PCB 和结构做出来。

## 根因（三层，同一件事）

1. **应力超幅只要求挂一件 design 或 validation 待办**（`audit_severe_stress`）。挂 validation 就算合规，
   于是“先做出来再测”替代了“把热边界交给 PCB 和结构”。
2. **框架早有这类规则，ASG 不执行。** 准则里 `closing_stage` 在原理图之后、`coverage: handoff` 的规则，
   本板适用 31 条，例如 G08-047“关键发热器件有散热接口表”（asg_action：每颗关键器件一行，写散热面、路径、总热阻目标、
   允许局部温度、壳到环境目标、所在面或朝向；“这是对 PCB 和结构的输入”）、G06-024 爬电间隙约束交 PCB、
   G08-019 电阻要求的 PCB 最高温度、G05-023 走线载流。审计把它们列进 `guidelines.downstream`，
   但按 2026-11-08 的决定“没引用的不报待办，不挡打包”，31 条一条也没交出去。
3. **载体是选做的。** SKILL.md 和 requirements-to-intent.md 第 4 节都写了“铜面积、散热器、布局约束写进
   《结构与PCB设计要求》技术转交文档……PCB 阶段只负责实现并实测这个热边界”，但这份文档“需求要求时才写”，
   没有审计核对；报告“技术转交要求”只收 `status: handoff` 的待办。

所以修法不是给热单独打补丁，而是把“下游约束”变成有固定载体、有审计、进报告的东西，热只是其中最重的一类。

## 改法

### 1. 下游约束表成为必写文档

- 文件 `设计资料/下游约束表.md`，登记为证据，`carrier: DOWNSTREAM`。取代选做的《PCB与结构要求》《结构与PCB设计要求》。
- 每块板都写（G08-047 等对 `board: true` 适用，任何板都有下游约束）。
- 一行一条约束，列：

| 列 | 写什么 |
|---|---|
| 编号 | `D-<序号>`，报告和计算引用它 |
| 接收方 | PCB / 结构 / 样机验证 / 生产 / 固件 |
| 对象 | 位号、网络或边界 |
| 约束 | 定量边界，不写“注意散热”这类无数的话 |
| 依据 | 计算编号、准则编号 |
| 验收 | 怎样判做到了：测什么、在什么工况、门限多少 |

- 热类示例（本板 U301）：接收方 结构+PCB；约束“结到环境热阻 ≤ 21.9 ℃/W（1.83 W、45 ℃ 环境、结温 ≤ 85 ℃）；
  手册 θJA 32.3 ℃/W（p17）达不到，须加顶面散热片或导热垫接壳；PCB 在 U301 地球下打满过孔接 L2/L5 地平面，
  正面留散热片禁布区和固定位”；依据 RF-TJ、G08-047；验收“45 ℃、2T2R 满输出实测壳温，用 ΨJT 换算结温 ≤ 85 ℃（G08-029）”。

### 2. 审计核对（`audit_design_closure.py`，新设 `downstream_version: 1`）

| 核对 | 错误码 | 挡打包 |
|---|---|---|
| 适用准则里关闭阶段在原理图之后的，每条至少一行引用，或在 `guideline_scope.not_applicable` 写理由 | `downstream_constraint_missing` | 是 |
| 温度类应力风险（`max_c`、`tj_percent`、`margin_c`），没有指向一件 open 的 design 待办（即不靠改原理图解决）的，计算的检查写 `downstream: [D-x]`，该行依据里写这条计算 | `stress_risk_without_downstream` | 是 |
| 应力超幅（任何量）同上；原有“挂 design 或 validation 待办”的要求不变：validation 负责确认，下游约束负责实现，两者不互相代替 | 同上 | 是 |
| 行缺接收方、约束、验收任一列，或接收方不在五类里 | `downstream_row_incomplete` | 是 |
| 引用了不存在的 `D-x` | `downstream_unknown_row` | 是 |

- 没写 `downstream_version` 的旧记录只出提示，不报错，旧工程和测试夹具不受影响。新设计必须写 `downstream_version: 1`。
- 局限照实写：审计只能核“有这一行、行写全了、依据指对了”，热阻目标算得对不对由 SR 审查核
  （G08-047 的 sr_check：“核表内数字与计算一致”）。

### 3. 报告

- “技术转交要求”一节改为按接收方分组，内容 = 下游约束表各行 + 现有 validation/pcb 的 handoff 待办；
  挂在 P0/P1 应力上的行排在最前，标出等级。
- “结论”加一行：技术转交 PCB n 条、结构 n 条、样机 n 条……
- “应力风险”表的“超幅待办”列旁加“下游约束”列，写 `D-x`。
- “未关闭项”里 validation 待办若对应下游约束，写“实现见 D-x”。

### 4. 不改的

- 待办的阶段不加“结构”：接收方写在约束表里，待办 schema 不动。
- 2026-11-08 的决定对其余准则不变：能淘汰候选、改变选型、进入计算之外的准则仍不要求逐条引用。
  **只把关闭阶段在原理图之后的那部分收紧**：它们本来就写着“交下游”，不交出去就等于没做。这是对 11-08 决定的局部收回，需要你明确同意。

## 测试

- 审计：缺下游约束表；表缺一条下游准则；写了不适用理由则通过；温度应力风险无 `downstream`；有 design 待办时不要求；
  引用不存在的行；行缺列；旧记录无 `downstream_version` 只出提示。
- 报告：技术转交按接收方分组、P0/P1 行排前、结论行计数、应力风险表的下游列。
- 全量测试跑通；`check_ledger.py` 纲要哈希与新确认记录一致。

按新规则补写 `设计资料/下游约束表.md`（31 条下游准则 + U301 热边界），重跑审计、重新生成报告、打包；
把热相关的几行发给正在布线的 PCB 会话；PPT 第 2 页那一行改成“已转交 PCB 和结构”。
