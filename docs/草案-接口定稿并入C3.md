# 草案：接口定稿并入 C3（模块编号与执行顺序一致）

日期：2026-11-10。用户原话：“现在这个运行的顺序，和标号C1～C6没有顺序的对应起来。可以修改成能力和执行的顺序对应起来吗？”；选定“按方案A”。

## 目的

现在任务 C2.2 接口定稿要读 C3 的块文件，排在 C3 之后、C4 之前，C2 与 C3 互为上游，执行顺序是 C1 → C2.1 → C3 → C2.2 → C4 → C5 → C6。
把接口定稿移到 C3 末尾成为任务 C3.3，执行顺序变成 C1 → C2 → C3 → C4 → C5 → C6，上下游单向。模块数、能力项数、`interfaces.json` 的格式都不变，只是产出方由 C2 改为 C3。

## 纲要逐句改动

### 1. 能力目标第 3 项（SKILL.md 能力七项）

原：
> 3. **功能电路选得合适**（C3）：选定方案的适用范围覆盖本板工况；都能满足的候选里选结构最简单、依赖最少的，选更复杂的要有需求、标准或手册上的理由；核心器件靠保证值覆盖决定条件。

改：
> 3. **功能电路选得合适**（C3）：选定方案的适用范围覆盖本板工况；都能满足的候选里选结构最简单、依赖最少的，选更复杂的要有需求、标准或手册上的理由；核心器件靠保证值覆盖决定条件；**按核心器件的端口限值把块与块之间的接口参数定下来，各块据此能独立设计。**

第 2 项（C2）不改：“块与块之间用少数几个参数就能说清”仍是 C2 划块的要求，C2 写的是预算。

改：
> 主流程按 C1→C6 排列，串起来就是从需求做新设计的默认编排。先弄清……
