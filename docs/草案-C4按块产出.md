# 草案：C4 按块产出，C5 合并

2026-11-09，已按“按草案写入”实施（纲要哈希 6209cca419f72e71）。实施时多做的两处：
- 需求级的核对（需求追溯、依赖待办、每条需求有计算核对）只在 C5 做：单个块的计算只核到部分需求。
- `check_module.py C4 --block` 只取本块的计算、引脚处置、待办链接和器件性能记录；块设计都写完后不带 `--block` 再跑一次才记指纹。

## 依据

- 用户原话：
  - “第三项看起来，不同的功能电路是无法严格划分的，但是这确实也是在电路中的问题。你建议我怎么处理？”
  - 对四条规则（器件归属唯一、网络共享、参数写进流向、耦合紧就合并）先做往返验证：“可以”；
  - “开始起草第二步（C4 按块产出）的纲要草案”。
- 往返验证（`scripts/blocks.py`，三块板）：
  - 653 个器件归属都唯一；
  - 按页切分，跨块的只有电源/地和标准接口，每种接口写几个参数就够；
  - 耦合紧的地方都在页内，例如 PoE 的 U1 同时是受电控制器和反激控制器。

## 1. 要定的四件事（草案按“建议”写）

| 事项 | 建议 | 理由 |
|---|---|---|
| 块的产品 | `record/blocks/<块>.json`，格式即 `blocks.py` 的块设计：器件（值、规格、料号）、块内网络、端口、NC 与未用脚处置、本块网络的标注 | 往返验证已证明能逐脚合回整板 |
| 端口怎样对上 | C2 在每条流向上写它承载的整板网络名 `nets` 和接口参数 `params`；地网络按电压域的 `ground` 命名。C4 的端口只能用这些网络名 | 端口名字由上游定，各块才接得上；参数让 C4 不必看别的块 |
| 位号 | C2 给每块一个编号段（如 PSU 用 100–199），C4 在段内编号；合并时不改号，重号报错 | 合并时改号会让计算、性能要求里引用的位号失效 |
| 接口件 | 上拉、电平转换、隔直这类件，C5 自己写进整板层块 `blocks/BOARD.json`；要改块内设计的回到 C4，根因在划分的回到 C2 | 与签名草案一致 |

计算、外围核对表 `reference-input.json`、性能要求 `component-requirements.json` 仍是 C4 的工作记录，每块的条目用位号区分，不拆文件；C5 不读它们（约定 1）。

### 2.2 C2.1（纲要）

在“架构记入 `record/architecture.json`……留给任务 C3.1。”之后加一段：
```
每条跨块流向写它承载的整板网络名（`nets`）和接口参数（`params`：电源轨写电压范围与最大电流，信号写电平、方向与驱动方式，模拟量写量程与源阻抗，差分对写差分阻抗）；地网络按电压域的 `ground` 命名。各块端口只用这些网络名。
块的边界放在少数几个参数就能说清的地方：两块之间要靠控制环、共用一颗芯片或多条模拟连线才能工作的，合成一块。每块给一个位号编号段。
```
做完的标志末尾加：`每条流向有网络名和接口参数；每块有位号编号段，各段不重叠。`

### 2.3 C4 开头（纲要）

原文：
```
给定输入：块规格与 `record/block-circuits/<块>.json`（方案与核心器件）。产出：`reference-input.json`、计算记录、`component-requirements.json`、块设计的设计网表。
```
改为：
```
C4 每块做一次。给定输入：本块的块规格、与本块相连的流向（网络名与接口参数）、`record/block-circuits/<块>.json`（方案与核心器件）。产出：块设计 `record/blocks/<块>.json`；工作记录 `reference-input.json`、计算记录、`component-requirements.json`。
本块的设计只依据这些输入，不读别的块；流向参数不够用或不成立时，回到 C2。
```

### 2.4 新任务 C4.4 块设计（纲要）

接在 C4.3 之后：
```
#### C4.4 块设计

把本块写成块设计 `record/blocks/<块>.json`（格式见 [modules.md](references/modules.md)）：器件、块内网络 `{name: [ref.pin]}`、端口、`no_connect`，以及本块网络的 `net_roles`、`net_voltages`、`external_supply`、`filtered_supply`。
器件的值、性能规格、采购定义方式与选型状态由任务 C4.2 的性能记录按位号生成，不另写默认值；记录不完整或候选未核准的保留真实状态。
位号在 C2 给本块的编号段内。端口用流向给的整板网络名，块内网络不与端口重名。
每个物理引脚要么接入网络，要么有依据地标 NC；不接的脚和按手册接地、上下拉的未用脚，逐脚写手册规定的处置和页码。
本块输出的电源轨写最坏最高电压和来源。值写设计值，不留库默认名或占位。用 `net_roles` 区分 power/return/signal，至少覆盖电源轨与阈值/反馈等易混淆网络。
只由连接器引入的电源或地、经一颗串联件从已有电源派生的供电网，逐网声明 `external_supply`、`filtered_supply`。

做完的标志：本块每个物理引脚接入网络或有依据地标 NC，处置有手册页；端口都是流向给的网络名；位号都在本块编号段内；本块输出的电源轨写了最高电压；没有占位值和未编号位号。
```

```
#### C5.1 设计网表

用 `scripts/blocks.py merge` 把各块的块设计按网络名合成整板设计网表 `electrical-intent.json`：同名端口接成一个网络，每个器件的 `fields.Circuit` 写所属块。合并报错（块内网络重名、端口没有对端、位号重复、同一网络各块的角色或电压不一致）时，按原因回到 C4 或 C2，不在 C5 改块设计。

`object_matrices.py` 按本版设计网表列出的矩阵与状态表逐格有结论（`matrix_version 1` 的审计没有 `matrix_cell_missing`、`matrix_cell_failed` 和 `matrix_*` 错误）。
```

## 3. 跟着改的实现（第二步之内）

- `architecture.py`：流向的 `nets`、`params`，块的位号编号段 `ref_range`，并检查编号段不重叠。
- `blocks.py`：
  - 合并时位号重复直接报错，不再改号；
  - 端口要在流向的 `nets` 或电压域的 `ground` 里；
  - 写 `fields.Circuit`；
  - 去掉按分页方案拆分的入口，只留给往返验证用。
- `check_module.py`：
  - C4 关卡按块运行，用 `--block`：核对本块块设计（引脚处置、端口、编号段），计算和性能要求按位号只看本块；
  - C5 关卡先合并，再跑现有整板审计；
  - `OUTPUTS`、指纹加上 `blocks/`。
- `audit_design_closure.py`：
  - `--module C4` 的引脚表与引脚处置改为读块设计；
  - 整板审计仍读合并后的 `electrical-intent.json`。
- `references/modules.md`、`requirements-to-intent.md` 第 5 节：块设计格式、流向写法、合并规则。
- 测试：
  - 块设计与合并；
  - C4 按块关卡；
  - 用三块板副本补 `nets`、`params`、编号段后跑 C4、C5 关卡。
