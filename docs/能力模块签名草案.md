## 0. 共同约定（三条）

### 约定 1：模块之间只通过“产品”联系

- 每个模块只有三样东西：**输入**、**产品**、**关卡**。
  - 输入是上游模块的产品，或外部给的内容；
  - 产品是一个独立文件，带格式版本，写明包含什么、不含什么；
  - 关卡检查产品合法、自洽。
- 模块不读别的模块的工作记录，包括计算、候选比较、待办。工作记录只属于产出它的模块自己，供审计和人查阅。
- 只要产品格式不变，一个模块可以单独修改、单独评测、单独替换，不影响别的模块。

### 约定 2：发现问题，向上游发“回溯请求”，不直接改上游

下游模块发现上游产品有问题时，写一条回溯请求：

```json
{"to": "C3", "block": "PSU", "problem": "给定方案在 37 V 输入、满载时占空比超过控制器上限",
 "evidence": "calc:C-DUTY", "suggestion": "改用占空比上限更高的控制器，或改两级方案"}
```

- **由上游模块按请求修改自己的产品**，并重过自己的关卡；下游不直接改上游的文件。这样每个产品始终只有一个负责的模块，修改也一定经过它的关卡。
- 上游改完后，凡是用到这个产品的下游模块都要重做（由 `modules.json` 的指纹自动标出）。
- 回溯可以跨级。比如 C5 发现两块电平不相容，根因在 C2 的电压域划分，请求就直接发给 C2。
- 用户也是一个“上游”：需求有缺口时，C1（或任何模块）向用户提问，形式和回溯请求相同。

### 约定 3：谁来执行回溯

| 运行方式 | 回溯请求怎样处理 |
|---|---|
| 串联运行（整板设计） | 编排层把请求交给目标模块；目标模块修改产品、重过关卡；下游按指纹重跑 |
| 单独运行（评测、分工） | 上游不在场，回溯请求本身就是输出的一部分，评测时判断它提得对不对 |

为防止来回反复：
- 同一个问题回溯两次仍没解决，就停下来问用户；
- 每次回溯都记一行，写明谁发给谁、为什么、结果如何，放进报告。

### 从第 1 稿删去的内容

| 第 1 稿 | 处理 |
|---|---|
| “依据”“隐藏输入”两个模板项 | 不再作为契约项。工作记录归模块自己管；运行环境（模型、技能版本、共用层、知识库快照）由工具自动记录，每个模块不必另外声明 |

## C1 需求理解与澄清

| 项 | 内容 |
|---|---|
| 输入 | 需求原文；可选：用户对澄清问题的答复，或代答授权 |
| 产品 | `requirements.json`：每条需求的编号、可验收的条文和来源；降额等级；产品基线；用户暂缓、按建议条文设计的假设。**不含**任何设计决定 |
| 提问 | 需求缺口、含糊、矛盾，每问附建议条文 |
| 关卡 | 每条需求有编号、条文和来源；没有未答复的问题；降额等级已定 |

## C2 板级方案

| 项 | 内容 |
|---|---|
| 输入 | C1 产品 |
| 产品 | `architecture.json`：功能块、电压域、电源树、隔离边界、跨块流向、对外接口；每块的块规格，关键指标写成字段。**不含**块内拓扑和器件 |
| 回溯 | 需求互相矛盾，排不出可行划分时发给 C1 |
| 关卡 | 现有架构检查；每条需求落到至少一个块或整板 |

## C3 块电路选择（每块一次）

| 项 | 内容 |
|---|---|
| 输入 | 一个块的块规格和它引用的需求；降额等级 |
| 产品 | `block-circuits/<块>.json`：选定方案、核心器件与角色、决定条件的本板取值、留给 C4 核算的数值。**不含**外围器件和数值 |
| 回溯/提问 | 块规格没有可行方案时发给 C2；选型确认要问用户 |
| 关卡 | 唯一的选定方案；核心角色都有确认记录；与其他候选比较过，或写明只有一种可行方案及查过的范围 |

## C4 详细设计与器件选型（每块一次）

| 项 | 内容 |
|---|---|
| 输入 | 块规格；C3 产品；相关需求；降额等级 |
| 产品 | `blocks/<块>.json` 块设计：本块的器件（料号或采购规格、数值）、块内网络、引脚处置、对外端口（对应 C2 的流向）、器件性能要求。**不含**跨块连接 |
| 回溯 | 方案在某工况下不成立时发给 C3；块规格本身不可实现时发给 C2 |
| 关卡 | C3 留下的数值都由计算关闭；每个引脚有处置；没有不成立的计算；需要核算的器件都有性能要求 |

## C5 全板闭合

| 项 | 内容 |
|---|---|
| 输入 | C2 产品；各块的块设计 |
| 产品 | 整板 `electrical-intent.json`：按流向连接各块端口、统一编位号、补 NC、电源轨角色、网络电压；闭合结论：矩阵与状态表、FMEA、EMC 端口矩阵。**不含**图面信息 |
| 回溯 | 跨块不相容、要改块内设计的发给对应块的 C4；根因在电压域或流向划分的发给 C2。只需加接口件（上拉、电平转换、隔直）的，C5 自己加，记为整板层的器件 |
| 关卡 | 现有 C5.1、C5.2 的做完标志 |

## C6 原理图绘制

| 项 | 内容 |
|---|---|
| 输入 | 整板设计网表；可选：板级方案（作分页参考） |
| 产品 | KiCad 工程、`schematic.pdf`、导出网表、`BOM.csv`、`page-plan.json`。**不含**任何电气改动 |
| 回溯 | 网表不合法（引脚号不存在、符号缺失）时发给 C5 |
| 关卡 | 现有 C6.1–C6.5 的做完标志 |

## 要逐项讨论的点

1. 三条共同约定是否就是你要的“独立可解耦 + 可回溯”。
2. 三处结构变化要不要做：
   - C1 产品拆出 `requirements.json`；
   - C3 产品拆出 `block-circuits/`；
   - C4 按块产出 `blocks/`，C5 再整合。
3. 逐个模块过一遍输入、产品和回溯对象。
