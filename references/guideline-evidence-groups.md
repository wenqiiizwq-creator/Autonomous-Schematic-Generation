# 必写的设计文档：FMEA 与 EMC 端口矩阵

> 读者：ASG 运行者与维护者。数据在 [guideline-evidence-groups.json](guideline-evidence-groups.json)，`audit_design_closure.py` 按它核对。

共用设计准则只有能淘汰候选方案、改变选型或进入计算的才逐条落实（SKILL.md 任务 1.3、2.2、2.3；用户 2026-11-08 按草案实施），
其余按设计动作照做，不要求逐条引用，也不要求为覆盖准则写文档。审计在 `design-closure-audit.json` 的 `guidelines` 里列出适用（`applicable`）、
已引用（`covered`）和没引用（`uncited`）的准则，供审查对照，不报待办，不挡打包。

FMEA 和 EMC 端口矩阵直接支撑“设计合理”，**有对外连接器的板必须写**：

| 文档 | `carrier` | 对象 |
|---|---|---|
| FMEA | `FMEA` | 每个对外连接器位号 |
| EMC 端口矩阵 | `EMC` | 每个对外连接器位号 |

写法：文档放 `设计资料/`，在 `design-closure.json` 登记一条证据，证据条目写 `carrier: FMEA` 或 `carrier: EMC`。一份文档可以由几条证据共同承担，几份文件合起来核。
标题按 JSON 里 `sections` 的 `name` 起，一节对一项，不必写准则编号。

核对：
- 章节：文件里某个标题行（`#` 开头），或某个表格的表头格，含 `match` 中任一词，就算有这一节。标题下到下一个同级或更高级标题之间要有正文，表格要有数据行，否则算空。
- 对象：设计网表里的连接器位号（不含测试点、机械件）都要在这些文件里以独立词出现（`J1` 不算出现在 `J10` 里，`J1～J4` 也不算写了 J2）。
- 有对外连接器却没登记、缺章节、空章节或缺连接器，审计记 `design_document_incomplete`（INCOMPLETE），打包被拒，写明缺什么。没有对外连接器的板不要求。
- `carrier` 写了别的名字记 `guideline_carrier_unknown`。

其他设计文档（需求追溯、工况矩阵、接口定义、最坏工况分析说明、隔离与绝缘、热分析说明、可测试性与生产、PCB与结构要求）按需求选做：需求或下游要求时写，写了就登记为证据；不写不挡交付。

## 局限

章节与对象核对只能证明写了、对象写全了，不能证明写得对；写得对不对，靠 SR 审查。
