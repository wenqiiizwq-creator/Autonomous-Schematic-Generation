# 从需求文档到设计网表

新设计或新增功能时使用：把受控需求文档变成一份可绘制、可验证的整板设计网表。
设计网表从需求和原厂资料独立写出，不能从草稿原理图回抄；回抄只能证明自洽。

## 1. 读需求，建需求清单

- 读项目受控的需求文档（用户需求、工程规格、范围与交付），逐条记下需求 ID、要求和适用边界。
  只用已确认的条目；不替用户补产品要求。
- 待确认、含糊或冲突而设计要靠它定的，按 [需求澄清](requirement-clarifications.md) 当场问用户：
  任务 1.1 一次汇总提问，之后各任务中途发现的也停下来问；每问附建议条文，答复写回需求清单再往下设计，
  不先画一版再问，也不留到交付时问。缺厂家资料、设计没做完、属于后续环节的事项不问。
  成本、体积等优化目标用于取舍，不当作硬门槛。
- 分清三类事项：原理图要实现的电路；固件、结构、PCB 要落实的事项（写技术转交说明，不画进原理图）；
  验证与认证事项（记录，不在出图阶段关闭）。

## 2. 功能分解与追溯

在工程目录里保存一张追溯表（Markdown 即可，工具不检查它）：

| 功能 ID | 功能 | 需求 ID | 实现方式 | 页面 | 状态 |
| --- | --- | --- | --- | --- | --- |
| F-PWR-01 | 3.3 V 辅助电源 | REQ-PWR-002 | LDO | 02_ldo | 已确认（CONFIRMED） |

每条影响电路的需求至少对应一个功能；没有对应的需求写明原因（属固件/结构/验证）。
实现方式写“模块”时，模块外部必需电路仍要画出（见 [symbol-and-peripheral-contracts.md](symbol-and-peripheral-contracts.md)）。

## 3. 架构与分页

按 [reference-driven-board-design.md](reference-driven-board-design.md) 画第 1 页 `System_block`：
电源与信号流向、隔离边界、接口和各页编号。按功能、隔离/电压域和可读面积分页，
页面 ID（如 `02_ldo`）在追溯表、设计网表和文件名中保持一致。

## 4. 选型、外围电路要求与计算

- 每个核心器件记录：确切 MPN、数据手册版本/哈希/实际阅读页码、物理引脚表、典型应用、
  必需外围、可选/DNP 支路。分立器件也要按确切订货型号核对引脚（同族通用符号可能脚序不同）。
- 需要机器核对时写 `reference-contract.json`，出图后用 `verify_schematic.py --reference-contract` 检查。
- 数值计算按 [calculation-preflight.md](calculation-preflight.md) 记录保证条件；条件不覆盖时结论只能是
  条件成立（CONDITIONAL）。
- **工况与角点清单**：每条定量需求和每个会改变状态的节点，至少核下面几类，未核的写进待办清单：
  1. 上电与热插拔：电源从 0 阶跃时，经栅漏/栅源电容、密勒电容、去耦和 RC 节点耦合到被开关的输出和
     控制脚的瞬态，包括“默认关”的输出在接入瞬间是否出现脉冲；
  2. 关断、待机与掉电：OFF 态的静态电流（含输入、开漏和电容漏电的最大值）、反向或反灌路径、
     电源跌落时 RC 节点能否复位；
  3. 全温角点：门限类参数按最不利温度取保证极值（例如 VGS(th) 取最高工作温度下的最小值），
     不用 25 °C 的值代表全温；
  4. 引脚应力：开漏/推挽输出直接给电容充放电、驱动 LED 或负载时，峰值和持续电流不超过
     手册的推荐工作值，必要时加限流电阻。
  5. 阈值窗口：每个保护/检测/钳位阈值（稳压管+电阻进保护脚、分压进比较器、栅源钳位等）两侧都算：
     正常工作最高点（全部工作档位的最高输出、纹波、漏感尖峰、温漂、元件容差）低于动作下限，不误动作；
     动作上限低于被保护对象耐受值或需求保护点，保护有效。阈值按实际绕组/分压比折算到被保护量，
     不能只写目标值。记录格式见 [design-closure.md](design-closure.md) 的 `kind: "threshold"`。
  6. 工作包络角点：最低/最高输入 × 空载/轻载/满载 × 每个输出档位的组合，逐个核控制器在该点的工作模式和时序界限
     （最短导通/关断时间、跳周期、高低压档判别、谷底锁定），不能只算额定点；例如 21 V 轻载时副边导通时间
     短于同步整流的最短导通时间设置，或最低输入被判成高压档使 PFC 功率能力不足；
  7. 单点故障：反馈开路或短路、光耦失效、检测电阻开路、偏置丢失等单一失效下，被保护量（输出电压、母线、结温）
     从失效开始的上升轨迹，对照保护链的检测与关断时间；保护必须在被保护对象越过额定前动作。
  8. 降额：关键器件与特殊器件在以上角点和瞬态下的电压、电流、功率与温度应力，按 [器件应力规范](stress-spec.md) 判，
     降额值取 [降额规范](derating-rules.md) 中本项目等级那一列（记录写法见 [design-closure.md](design-closure.md) 的 `derating_version`）；
     常规件的规格写出的最低额定 = 最坏应力 ÷ 本级降额系数。
- **审查常问的设计闭合项**（独立审查几乎每轮都会要，设计阶段一次算清并写进设计依据，附位号与 `checks`）：
  1. 隔离屏障逐成员：变压器、每只光耦、Y 电容各自承受的复合重复工作电压（直流 + 开关峰值）、频率、海拔/气候系数，
     对照所选变体的加强绝缘允许条件（VIORM、绝缘系统、Y1 额定），不用短时耐压代替；
  2. 偏置与低压供电：辅助绕组最低档 + 整流压降 + 线性偏置管 VGS/齐纳在实际电流下的组合，算控制器 VCC 谷值对最大 UVLO 关断阈，
     以及 PD 控制器 LDO 在最低 VDD（5V 合同）下的输出和并联负载（VCONN、光耦）；
  3. 线性工作的开关 MOS：连续 VDS×ID 工作点对直流 SOA；沟槽 MOS 多数不保证，换线性额定器件或 BJT；
  4. 光耦传输：每路按实际 IF 查 CTR 曲线，寿命末期用声明的折减系数（写明取值依据），接收端所需电流两侧留裕量；
  5. 电解电容：按各工作模式的电流频谱和厂家频率/温度系数折算纹波，用厂家寿命公式和任务谱算十年损伤，给允许热点；
  6. 市电侧保护配合：熔断器分断能力对照 GB 4943.1/IEC 62368-1 规定的预期短路电流（不是向熔断器厂家要），
     NTC 热态再启动的浪涌对桥堆/熔断器 I²t；
  7. 保护链能量：输出过压从检测到开关断开期间端口可达的电压/能量，对照每档合同允许值；
  8. 连接件与通用料：交流输入连接点、脉冲电阻、旁路电容的可采购规格写入 BOM 约束；
  9. 固件配置表：PDO/PPS/AVS 能力、线缆识别与限功率、NTC 切档阈值、OVP 编码、GPIO 角色、各故障的恢复/锁定策略，
     作为设计交付定型；镜像烧录与读回属生产环节，写进技术转交。
  这些项算不过才是设计缺口；算得过就把结论和条件写进设计报告，审查方据此关闭，不再以“缺资料”往返。
- 原理图阶段不定封装、不做散热实现：`footprint` 可以留空；铜面积、散热器、布局约束写进
  《结构与PCB设计要求》技术转交文档。**器件热可行性属于选型**：线性稳压、采样电阻、钳位/泄放电阻等
  最坏工况功耗达到约 0.3 W 或封装额定的一半时，用手册 θJA（或 θJC+假设的板级热阻，写明假设）
  和整机内部最高环境温度估算结温/温升，作为一条带 `checks` 的计算；超出额定就换封装或换方案，
  不能写“待核”交给PCB。PCB 阶段只负责实现并实测这个热边界。
- 新下载的数据手册按 SKILL.md 的资料规则同时存入 HardwareWiki。

## 5. 写整板设计网表

一份 `electrical-intent.json` 覆盖整板，格式如下（充电器工程实际使用的形式）：

```json
{
  "schema": "project-hardware-intent-v1",
  "revision": "v0.1.0",
  "components": [
    {"ref": "U201", "lib_id": "Regulator_Linear:AMS1117-3.3", "value": "AMS1117-3.3",
     "footprint": "", "mpn": "AMS1117-3.3", "datasheet": "datasheets/AMS - AMS1117.pdf",
     "fields": {"Circuit": "02_ldo", "Requirement": "REQ-PWR-002",
                "Evidence": "DS rev C p5 Fig 3", "Status": "Selected"}}
  ],
  "nets": {"+5V": ["U201.3", "C201.1"], "+3V3": ["U201.2", "C202.1"],
           "GND": ["U201.1", "C201.2", "C202.2"]},
  "no_connect": []
}
```

- 每个物理引脚要么在一个网络里，要么在 `no_connect`；NC 要有手册依据。
- `fields.Circuit` 是页面 ID，`pages.page_intents()` 据此拆页。
- `mpn`、`datasheet`、普通 `fields` 会作为隐藏属性写进原理图，`verify_schematic.py` 逐字段比对，值一律写字符串。
  新[器件性能流程](component-requirements.md)从单一记录生成 IR 与 BOM；版本标记为 `component_requirements_version: 1`。
  合同器件的 `Performance` 例外为可见字段：完整短规格，或指向 `Sheet.performance_notes` 生成的同页技术注释。
  `RequirementSpec` 是采购限制，`SelectedSpec` 是已核准实际值，候选留在 `performance_contract.selection`，不得写正式 MPN。
- 哪些器件必须写确切 `mpn` 和 `datasheet` 由 [part-roles.md](part-roles.md) 第 1 节的分级决定（与 schematic-review 对齐）：
  关键器件和特殊器件必须写，并用 `fields.Kind`、`fields.KindSource`、`fields.KindQuote` 按本器件手册声明器件类型；
  定制磁件用 `fields.DesignSheet` 指向磁件设计单代替 `datasheet` 和类型声明；常规件写 `value` 和规格字段，写出算得的最低额定
  （每个电容写耐压，每个电感写额定电流）。工作电压高于 30 V 或接市电的网络列在顶层 `high_voltage_nets`，
  据此判定高压连接器、继电器、电源路径上的 NTC 和安全防护位置；跨隔离与市电侧的器件写 `fields.Approval`（认证）。
  电阻和电容按知识库二级类写 `fields.Category`；检流电阻写阻值、容差和功率，功率电阻写容差和功率；
  功耗要考虑的电阻（判据见 [design-closure.md](design-closure.md) 的“电阻写额定功率”）旧格式 `value` 写成 `阻值/公差/额定功率`（如 `620/1%/0.125W`）；
  新合同器件保留标称值、由 `RequirementSpec/Performance` 明确容差和额定功率，仍执行相同功耗判据，不增加无依据默认值。
  `Requirement`、`Evidence`、`Status` 是建议字段，便于追溯，工具不解释其内容。
- 电源轨和地网络的网络名就是图上电源符号的 Value；不同地网络（初级地、次级地、端口地）用不同网络名，
  不能为了好看合并。跨页网络在每页用同名全局标签。
- 引脚编号来自确切 MPN 的数据手册，符号库只是载体。

### 连接器角色与外部供电

两触点自定义连接器在 `fields.ComponentRole` 写 `connector`，并在现有器件选型与用法依据中对应原厂资料位置与实际接触脚。
该字段让 `Sheet` 使用锚点画法，并供外供审计核对设计网表/KiCad 角色一致；它不是机械身份或电气额定值的证明。
常规 `Connector` / `Connector_*` 库已有显式连接器角色；普通 R/C 的二端分类不变。

板上没有 power_out 驱动、经连接器引入的电源/地网络，逐网声明
`external_supply: [{"net": "VCC", "pin": "J1.1", "reason": "主机引入电源，见器件选型与用法依据"}]`，
用 `Sheet.power_flag()` 每网放一个 PWR_FLAG。未声明的网不得放 PWR_FLAG。
`external_supply` 自动检查核对：每个 PWR_FLAG 都在已声明的网上；每个声明网恰好一个；声明的连接器脚在该网上；
该网没有板上 power_out 驱动；连接器的精确身份、装配状态与设计网表一致，声明触点及整个库引脚表都是 passive。
自动检查按缓存的 KiCad power/power_out 标记识别所有 namespace 的旗标，缓存缺失或继承无法解析记 INSUFFICIENT。
旗标只使用实际放置的 unit/body style 及适用的 common 定义；未使用的输出脚不能借给输入型实例。
重命名 KiCad 探针中每个旗标须恰有一个已知编号的实际 power_out 节点，类型或应用范围未知不能记 PASS。
原厂来源含义、供电能力、保护和完整性仍须在设计依据里单独论证。

器件的电源输入脚经一颗串联电阻、电感、磁珠或保险丝从已有驱动的电源取电时（例如 RC 滤波的模拟电源 AVCC），
KiCad 看不到无源器件传过来的驱动，必报 `power_pin_not_driven`。逐网声明
`filtered_supply: [{"net": "AVCC", "from": "PVCC", "via": "R1", "reason": "10 Ω/1 µF RC 滤波"}]`，
同样用 `Sheet.power_flag()` 每网放一个。自动检查核对：`via` 的设计网表库 ID 是 KiCad`Device:` 库中的电阻、电感、磁珠或保险丝符号（`R`、`R_Small`、`L`、`L_Small`、`FerriteBead`、`Fuse`、
`Polyfuse` 等；LED、灯泡、光敏电阻不算），或以 MPN 命名的非 `Device:` 库件加 `fields.ComponentRole`：`series_resistor`/`inductor`/`ferrite_bead`/`fuse`，已贴装、身份与 KiCad 一致、
恰好两只 passive 脚，一端在 `from` 的 KiCad 网、一端在声明网（网络名只允许页路径前缀）；`from` 所在 KiCad 网有板上 power_out
驱动（不计 DNP 器件）、是已声明的 `external_supply` 网，或是已合格的 `filtered_supply` 网（可链式）；声明网上至少有一个
电源输入脚、没有 power_out 驱动、恰好一个旗标；地/回流类网（按网络名或其电源输入脚的 KiCad 引脚名判断）只能与地/回流类网互相派生。
声明只解决 ERC 记账：按该脚最大电流核串联压降，并确认手册允许该脚串联阻抗；偏置馈电（如手册要求的串联大电阻）
与滤波电源分开写理由。逐条列入设计报告，并写明取值、压降和纹波依据。
串联件整体库表仍须恰两只 passive 脚，实际 KiCad 节点还须逐脚编号唯一、完整且类型为 passive；
不能用静态库类型覆盖实际脚类型，复合类型也不能拆出 passive 当作证明。
明确的 KiCad ComponentRole 须与设计网表相符；重复或矛盾的元数据不能作为资格。
即使设计网表未填写角色，明确的 KiCad 非串联角色也不能借 `Device:R` 等库 ID 获得资格。
缺 KiCad 角色的 legacy 项目保留既有设计网表角色兼容，仍不免除身份、类型和原厂来源复核。

核心引脚对照记录的 names/types 不接受空、空白或 `~` 别名；显式未分配的空 footprint 仍合法。

## 6. 开放项

未选型、参数待定、用户暂缓的需求列成待办清单，附关闭条件。用户暂缓的需求用 `requirement`
阶段，`clarification` 写对应的需求澄清，`assumption` 照抄其建议条文、`action` 写要用户定什么；
没问过用户的需求缺口不走这条路，按第 1 节先问再设计。图上用 `Status` 字段或注释
标明条件设计，不把它画成已完成的电路，也不编造料号或阻值。

每项关闭条件必须对应实际义务，记录：责任方、对象及状态/工况、缺少的具体输入或实施动作、
资料取得方法、可判定的通过边界和复验范围。已有局部证据写明支持到哪里，剩余边界另列；
没有数值边界的事项写可观察的验收条件。不能用同一句“补厂家资料、重新验证”代替逐项关闭条件。

区分外部资料缺失、设计保证未闭、工具覆盖缺口与后续环节 HANDOFF。例如工具不支持某种图形时，
关闭动作是有 KiCad 正反例的工具修正与复跑，或明确受限的 KiCad 图面审阅记录，不是索取器件电气资料；
PCB/光学/实测热的技术转交应写接收角色和验证范围，不能混成原理图本体保证。填写关闭计划不等于
执行整改或关闭待办；关闭后保留原项、实际新证据与复判结果。
