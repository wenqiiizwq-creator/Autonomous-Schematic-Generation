# 计算方法

类型：方法。层次：功能电路、器件。状态：在建（2026-11-09 起）。

回答：一类电路的元件值按什么顺序定、每一步用什么式子、输入取哪一端、算完要满足什么。

## 与设计准则的分工

设计准则写的是“必须成立什么”，多数是算完之后的核对条件，有的也带核对用的式子。本组件写的是**取值步骤**：从需求和器件手册出发，按什么顺序把元件值一个个定下来，使那些准则成立。

- 准则里已有的判据和工程取值，这里只写编号引用，不重抄。
- 一个步骤算出的量要满足哪条准则，在步骤里写出准则编号。`工具/rule_support.py` 据此生成 [准则支撑表](../准则支撑表.md)。
- 降额系数和应力判法在设计准则的 G10，这里引用。

## 条目格式

一类电路（或一类器件的选型）一个文件：

```
# <名称>

类别：计算方法（取值步骤）。
适用范围：哪类电路、哪种控制方式或器件类型；不适用的写明。
对应典型电路：../典型电路/<文件>.md（没有的写 无）

## 来源
- S1：<相对 ../HardwareWiki/raw/ 的路径>

## 已知条件
| 量 | 说明 | 谁给 | 来源 |      ← 谁给：需求、接口约定、器件手册、上一步

## 取值顺序
| 步 | 定什么 | 算式 | 输入取哪一端 | 算完要满足 | 来源 |
                                              ← “算完要满足”写准则编号或手册条件

## 相互牵制
哪个量改了，前面哪几步要重算。

## 算完之后的核对
逐条写要核的量和对应的准则编号；本条目没有覆盖、要另找条目算的也列出。

## 什么时候这套步骤不适用

## 算例（可选）
只用来源里自带的算例，逐个数注明页码；不用某块实际板子的数。
```

写法要求：

- 来源的写法和核对同 [接口约定](../接口约定/README.md) 的“来源的写法与核对”，条目要过 `python3 工具/check_sources.py`。页码用 PDF 文件页序，逐页抽取确认（`pdftotext -f N -l N`）；整本抽取后数换页符会数错。
- 每个输入写明取最小值还是最大值；取法的一般规则见 [最坏情况怎么取](最坏情况怎么取.md)。
- 式子写全，注明成立的条件和忽略了什么。来源里的式子有错的，按正确的写并注明原件哪里错了。
- 不写某块板的取值，不出现技能名。
