# 典型电路

类型：模式。层次：功能电路。

回答：一个功能通常怎么实现，有几种实现方案，各自在什么条件下适用，必须带哪些外围，要算哪些量，已知在哪里容易出错。
只写到电路这一层，不写具体型号的参数值；器件的数在 [`器件参数/`](../器件参数/README.md)，公式在 [`计算方法/`](../计算方法/README.md)。

2026-11-09 从设计技能的仓库迁来，共 40 个；迁入时清理了与技能有关的写法（见下）。

## 条目格式

一个功能一个文件 `<功能>.md`：

```
# <功能标题>
功能：一句话。
适用范围：功率、电压、频率、隔离等级。
电路类型：设计准则词表里的电路类型名（见 ../设计准则/准则登记/词表.json；多个用、分隔；没有对应类型写 无）

## 来源清单
- S1：<相对 ../HardwareWiki/raw/ 的路径>

## 选方案时比较的量（有几种方案时写）
| 方案 | …可比较的条件… | 来源 |

## 实现方案
### <实现方案名>
- 适用范围：这种方案在什么条件下优于别的方案，尽量写成数值条件
- 核心器件类：器件的类别，不写型号
- 必需外围：没有它电路不工作的元件
- 必算项（可选）：这种方案要核算的量，指到 ../计算方法/ 的条目
- 落实规则（可选）：这种方案落实的设计准则编号
- 已知坑（可选）：每条写来源
- 来源：S1 p4 这样的编号加页码

## 各方案共同要求（可选）
### <要求名>
不论选哪种方案都要落实的内容；不放在“实现方案”一节里，免得被当成一种方案。
```

来源用编号加页码，条目要过 `python3 工具/check_sources.py`。样例：[level-translation](level-translation.md)。

## 规则

- 每种实现方案必须有来源，没有来源的不写。已知坑每条引审查发现或手册页。
- 有可复用的新实现方案、判据或已知坑时按来源补写，不按篇数虚增。
- 必算项、已知坑和落实规则不要求填全。

## 来源的几种写法

- 手册、应用笔记、标准、书：在“来源清单”里编号，正文写 `S1 p4`。2026-11-09 以前的条目原来写成 `raw/Datasheet/…（p4 引脚）` 或 `datasheet:Datasheet/…#p4`，已统一改写。
- `审查发现：<审查名或板名>，<编号>`：这条已知坑来自一次设计审查证实的问题。审查记录在项目里，不在知识库，这里只留出处的名字。
- `设计评审：<日期>，<事项>`、`设计记录：<板名>，第 n 项`：来自设计过程中确认的问题，原记录同样在项目里。
- 核心器件类前面的两位数字（如“08 线性稳压器”）是知识库 `raw/Datasheet/` 的分类编号。
- 必算项里的 `g03_loop_pm_min` 这类名字是设计准则里工程取值的名字，数值在 `../设计准则/`。
