# 需求要素

类型：模式。层次：需求。状态：13 个条目已写（2026-11-09 首批 10 个，2026-11-10 第四轮加音频、无线与射频、高速显示与扩展接口三个端口条目），条目格式定型。

回答：要把一块板设计出来，需求里必须给定哪些条件；缺了哪一条，哪个方案取舍、哪个元件的取值或哪个保护的门槛就定不下来。

用法：拿到一份需求，先按板上的对外端口逐个查对应的端口条目，再查三个全板条目（板内负载、环境与寿命、安全与电磁兼容的前提），逐行问。每行“没写时”一栏说明这一项能不能用标准默认值，不能的就是必须问的。

## 与设计准则的分工

- 设计准则 G01（设计输入与工况）写“设计输入必须满足什么”：电源输入的工况清单要齐（G01-017），以及 −48 V、交流、USB Type-C/PD、工业 24 V 数字输入、军车 28 V、舰船交流、PoE 受电、正 24 V 各自的默认工况和数值。G06、G07、G08 写安全、电磁兼容、环境的前提要先给定。
- 本组件**不重写这些准则**：准则里已有的数值不重抄，写准则编号。它做的是把散在各准则里的条件，按端口种类和板卡工况归拢成“拿到需求要逐项问的清单”，并写明每一项决定设计里的哪一处。
- 准则没有覆盖、而标准或手册有数的，写出数并注明出处，同时登记在下面的“准则没有覆盖的端口和工况”，以后可提给设计准则。

## 条目格式

一类端口或一类全板工况一个文件：

```
# <端口或工况类别>

类别：需求要素（模式）。
适用范围：包括哪些端口；不包括的写明去哪个条目。

## 来源
- S1：<相对 ../HardwareWiki/raw/ 的路径>

## 总表（端口有几种用途时可分几张表，例如受电、供电）
| 条件 | 决定什么 | 没写时 | 准则 | 来源 |

## 缺了会怎样
最容易漏、漏了会改变方案的几项。
```

各列的写法：

| 列 | 写什么 |
|---|---|
| 条件 | 需求里要给定的条件，一行一个；带上它的给法（量什么、在哪一点量、有哪几种可选） |
| 决定什么 | 它决定哪个方案的取舍、哪个元件的哪个取值、哪个保护的门槛；尽量指到 `典型电路/`、`计算方法/`、`接口约定/` 的具体条目 |
| 没写时 | 标准或规范有默认值的写出处和默认值；准则已写的写准则编号；都没有的写“必须问” |
| 准则 | 对应的设计准则编号；准则没有对应的写“—” |
| 来源 | 写 `S1 p43`；这一行的内容全部来自准则时写“准则”（准则自己带出处） |

写法要求：

- 来源的写法与核对同 [接口约定](../接口约定/README.md) 的“来源的写法与核对”，条目要过 `python3 工具/check_sources.py 需求要素`。页码用 PDF 文件页序，逐页抽取确认（`pdftotext -f N -l N`）。
- 核对工具会把“决定什么”“没写时”两列里的数逐个到所引页里找，“条件”列不核。所以引了页码的行，这两列只写那一页上有的数；引到扫描件（抽出的只有水印）的行，这两列不写数，改写准则编号，或在“来源”写“准则”。一行引两份原件时，数要在每一份所引页里都找得到，所以一行尽量只引一份。
- 不写某块板的结论，不出现技能名和脚本名。
- 从器件手册来、需求不必给的条件，单列一张表并写明（见 [板内负载](板内负载.md)）。

## 准则没有覆盖的端口和工况

下面这些在条目里写了数或写成了必须问的条件，设计准则里还没有对应条目，以后可提给设计准则。

| 端口或工况 | 条目里写了什么 | 出处 |
|---|---|---|
| 传统 USB 连接器受电（Standard-A/B、Micro-B，没有 CC 脚） | 单位负载 100 mA，高功率设备上电先取不到一个单位负载、配置后不超过五个；高功率端口 VBUS 4.75～5.25 V、低功率端口 4.40～5.25 V；入口负载按 10 µF 并 44 Ω，超出要自带浪涌限流；挂起电流按 7.2.3 节及勘误。G01-026、G01-029 明确不套到传统连接器，只写了“另核” | USB 2.0 p199、p202、p204、p205、p206 |
| USB 充电口识别 | 专用充电口额定 0.5～5.0 A，带数据的充电口 1.5～5.0 A，设备从充电口最多取 1.5 A | USB 充电规范 R1.2 p56 |
| PoE 供电端 | 各级在供电端输出端的最小功率；输出电压与限流按表 33–11；环境 A、B 的隔离要求；线间短路与共模冲击耐受。准则只有受电端（G01-043～G01-064） | 802.3 摘录 p53、p76–77；802.3bt 概述 p2 |

## 待补

| 待补 | 原因 |
|---|---|
| 谐波电流与功率因数（交流入口） | 谐波电流标准（GB 17625.1、IEC 61000-3-2）原文未取得，交流入口条目里没有单列；GB 20943 只管电源类产品的能效 |
| 工业数字输出、模拟量的标准额定 | IEC 61131-2 原文未取得，设计准则已决定不再追原文（G01 资料缺口）；数字输出和模拟量只能写成必须问 |
| RS-232 的标准电气约定 | 知识库没有 TIA/EIA-232 原文，只用收发器手册说明给法 |
| 功能安全等级怎样影响电路 | 知识库没有 IEC 61508 原文，也没有准则 |
| 无线功能的型号核准与天线 | 没有资料，未写 |
| 未写的端口 | 三相交流、单对以太网和光口、电机与编码器端口、显示与音频端口、高速串行接口 |
| 按板卡类型的清单 | 现在按端口和全板工况分；各类板卡常见的端口组合和最容易漏的项，等板级架构模式建起来后再写 |
| 扫描件来源 | GB/T 17799.2、GB/T 17626.29、GB/T 4208、GB 4943.1 在知识库里是扫描件或文字抽不出，工具核不了数；相关行改引准则编号 |

## 与其他组件的关系

- 典型电路各实现方案的“适用范围”是从另一头写的同一件事：方案靠哪个条件取舍，那个条件就必须在需求里给出。本组件“决定什么”一栏指到那些方案。
- 需求给定的条件往往就是 [接口约定](../接口约定/README.md) 参数模板里源端或负载端的量的来源，例如直流输入的电压窗就是 [电源轨](../接口约定/参数模板/电源轨.md) 里源端的稳态电压上下限。
- 端口在故障和异常工况下要经受什么，以后在 [失效与异常工况](../失效与异常工况/README.md) 里写；这里只问需求有没有给出它们。
