# 板级架构模式

类型：模式。层次：整板。状态：14 个条目已写（首批 8 个，2026-11-10 补高可靠与可测试性 6 个），均过来源核对。

回答：整板这一层的结构问题怎么做——一条需求落到哪些功能块；电源树分几级、各级取什么电压；电压域和隔离边界放在哪；接地怎样划分和连接；保护分几层、支路怎样分；复位和时钟怎样分给多个器件；哪些功能应当合成一块，块与块之间怎样只用少数几个参数说清。每个问题有几种做法，各自在什么条件下合适。

## 与设计准则和其他组件的分工

- **设计准则**写“必须成立什么”，例如“每条配电支路在源侧有保护”（G05-019）、“上电时序在极值时间下满足约束”（G03-028）。准则不管选哪种结构。本组件写的是**有哪几种结构、各适用于什么条件、选了之后要补什么**，并在每个条目末尾的“对应准则”表里写出它支撑的准则编号。准则里已有的判据和取值，这里只写编号，不重抄。
- **[典型电路](../典型电路/README.md)**：一个功能块内部怎么实现。本组件只到块的层次，需要具体电路时指过去。
- **[接口约定](../接口约定/README.md)**：块与块之间交代哪些量。本组件每个条目有一节“块之间由此要交代的参数”，指到那里的模板，不在这里列量。
- **[计算方法](../计算方法/README.md)**：元件值按什么顺序算。本组件只写选结构时要比较的条件，算法指过去。
- **[失效与故障分析](../失效与故障分析/README.md)**：器件怎样失效。本组件的保护分层只写故障在块与块之间怎样传、靠什么挡住。

## 条目格式

一种结构问题一个文件，文件名就是问题名：

```
# <结构问题>

类别：板级架构模式。
回答：一句话。
适用条件：什么样的需求会用到它。
不在本条目：相邻的问题在哪个条目或组件。

## 来源
- S1：<相对 原件/ 的路径>

## 先要知道的条件（可选）
做这个选择之前，需求或手册要给出什么。

## 做法
### <做法 A>
- 结构：
- 合适：在什么条件下优于其他做法（附来源）
- 代价：
- 要补的措施：
（每种做法一节）

## 怎么选
| 做法 | 条件 | 判据 | 来源 |      ← “判据”列尽量写数值条件，数要能在所引页找到

## 块之间由此要交代的参数
| 参数 | 谁交代 | 模板 |       ← 指到 ../接口约定/ 的模板，不在这里列量

## 对应准则
| 准则 | 本条目补的是 |

## 不适用的情形
```

写法要求：

- 来源的写法和核对同 [条目规范](../条目规范.md) 的“来源的写法与核对”：条目开头 `- S1：<路径>`，表格最后一列叫“来源”写 `S1 p43`，正文写 `（S1 p50）`。页码用 PDF 文件页序，逐页抽取确认（`pdftotext -f N -l N`）。条目要过 `python3 工具/check_sources.py 板级架构模式`。
- 工具只核带“来源”列的表格行，且“条件、说明、参数”等列不核数。要核的数写在“判据”列；由两处来源合起来推出的式子（如单级降压的转换比条件）也写在“判据”列，两处都标上。
- 没有来源的做法和条件不写，记到下面的“待补”里，写明缺什么。
- 写条件和取舍，不写某块板的结论；来源里的例子注明“例”。
- 不出现技能名或脚本名。
- 一件事只在一处写：同一条件在两个条目都用到时，写在更直接的那个条目里，另一个条目指过去。
