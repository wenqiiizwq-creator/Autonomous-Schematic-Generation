# 设计工作流

`asg-design.js` 是把设计流程交给独立 agent 执行的编排脚本（Claude Code 的 workflow）。它不含设计规则：每个模块做什么、做完的标志和关卡是什么，仍以 `SKILL.md` 的主流程模块表和 `references/module-*.md` 为准。脚本只规定：

- C1–C6 和交付各用一个新的上下文执行，只读 `SKILL.md` 和本模块的细则；C4 可以一轮做一块。
- 每个模块做完，由另一个上下文实际运行本模块的关卡命令，通过才进下一个；没过就把错误原文交回本模块处置，超过限定轮数停下并报告卡在哪里。
- 模块发现上游产出有错，回到那个上游模块重做，下游依次重跑。
- 状态只记在设计目录里。要人确认或答复的地方（需求澄清、选型确认、未定项的决定），任务书里有答复或代答授权的按任务书办，没有的停下并返回问题；答复后用 `start` 从那个阶段接着做。

## 怎么用

在 Claude Code 里让它运行这个工作流（按文件路径，或把本文件链接到项目的 `.claude/workflows/` 后按名称 `asg-design`），参数：

| 参数 | 含义 |
|---|---|
| `workdir` | 设计目录的绝对路径 |
| `inputs` | 一段话说明需求文件在哪里、任务书在哪里（没有就写没有） |
| `delivery` | 交付目录的绝对路径。改版时用原来的交付目录：重新出图只换 `设计方案/` 里的原理图文件，PCB 环节放在同一个 KiCad 工程里的板子和板子设置保留 |
| `review` | 可选。改版时审查报告的路径；有它就先判断受影响的最上游模块，从那里重做 |
| `start` | 可选。从第几个阶段开始（1–7：C1…C6、交付） |

返回 `status`：`complete`（附交付目录和设计报告路径）、`needs_input`（附 `questions`）、`blocked`（附卡住的阶段和关卡错误）。

## 与审查工作流的关系

设计和审查是两个独立的工作流，各由自己的 agent 执行，不在同一个上下文里往复。两者只通过文件交接：本工作流的交付目录是审查的输入；审查报告是改版的输入。改版由人发起：带 `review` 另开一次本工作流的运行，交出新版的交付目录后，再另开一次审查的改版复审。

改了脚本后，同一个会话里按名称调用的仍是会话启动时读到的版本：新开会话，或按脚本文件路径运行。

某个模块或步骤发现前面的产出不够用时返回“回到上游”，脚本带着它的意见回到那一处重做；回退超过三次或意见指不到更前面的位置时停下，返回 `blocked`。
